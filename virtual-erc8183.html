Thesis

ทำไม ERC-8183 อาจทำให้ VIRTUAL น่าสนใจอีกครั้งในปี 2026

วิเคราะห์การ pivot ของ Virtuals Protocol จาก AI launchpad สู่ infrastructure layer ของ agent economy บน Ethereum

มีนาคม 2026 ~5 นาที
TL;DR สำหรับคนขี้เกียจอ่าน
  • VIRTUAL กำลัง pivot จาก launchpad/consumer AI story ไปสู่ infra story หลังการมาของ ERC-8183 ที่ออกแบบมาเพื่อให้ AI agents จ้างงาน จ่ายเงิน และเคลียร์งานกันบนเชนแบบ trustless ได้
  • จุดแข็งคือการอยู่ใกล้มาตรฐานของ Ethereum มากขึ้น แต่จุดเสี่ยงสำคัญคือ ERC-8183 เป็น open standard — คนอื่นก็ใช้ได้โดยไม่จำเป็นต้องใช้โทเค็น VIRTUAL
  • โอกาสมี แต่ไม่ใช่ของฟรี — ยังมีแรงกดจาก supply ฝั่ง treasury, ความเสี่ยงเรื่อง token value accrual และการแข่งขันจากแพลตฟอร์ม AI แบบปิดของฝั่ง Web2

ถ้าหันมามอง VIRTUAL หลายคนอาจยังติดภาพว่าโปรเจกต์นี้คือแพลตฟอร์มสำหรับ AI agents, AI characters หรือ launchpad ที่เคยได้ narrative แรงมากในช่วงต้นปี 2025

แต่ในเดือนมีนาคม 2026 ภาพนั้นเริ่มเปลี่ยนไปพอสมควร เพราะ Virtuals เอาตัวเองไปอยู่ในตำแหน่งใหม่ของตลาด ผ่านการร่วมพัฒนา ERC-8183 ซึ่งเป็นมาตรฐานสำหรับ "Agentic Commerce" หรือการทำธุรกรรม/จ้างงานระหว่าง AI agents แบบ trustless บน Ethereum

ถ้า narrative นี้เดินต่อได้จริง VIRTUAL อาจไม่ได้เป็นแค่เหรียญในธีม AI อีกตัว แต่กำลังพยายามขยับไปเป็น ชั้นโครงสร้างพื้นฐานของเศรษฐกิจ machine-to-machine บน EVM ซึ่งเป็นโจทย์ที่ใหญ่กว่ามาก

สิ่งที่ตลาดอาจยังมองไม่เต็ม: VIRTUAL กำลังเปลี่ยน "หน้าที่" ของตัวเอง

ก่อนหน้านี้ VIRTUAL ถูกเล่าในฐานะแพลตฟอร์มที่ช่วยสร้างและ tokenize AI agents แต่สิ่งที่ทำให้ thesis เริ่มน่าสนใจกว่าเดิมคือการเชื่อมกับมาตรฐานใหม่ของ Ethereum

ERC-8183 ถูกออกแบบมาเพื่อให้เกิด "งาน" บนบล็อคเชนโดยมี escrow และ evaluator เข้ามาช่วยตัดสินว่างานเสร็จจริงหรือไม่ ซึ่งทำให้การจ้างงานระหว่าง entities ที่ไม่ต้องเชื่อใจกันเกิดขึ้นได้

พูดแบบง่ายที่สุด — agent A อยากจ้าง agent B ให้ทำบางอย่าง ทั้งสองฝ่ายไม่รู้จักกัน ไม่อยากพึ่งตัวกลาง ต้องมีวิธีล็อกเงิน ส่งงาน และปล่อยเงินเมื่อเงื่อนไขครบ

เปิดงาน → วางงบใน Escrow → ส่งงาน → Evaluator ตรวจ → ปล่อยเงิน

นี่คือปัญหาที่ระบบชำระเงินแบบเดิมจัดการได้ไม่ดี โดยเฉพาะถ้าเป็นธุรกรรมขนาดเล็ก ทำซ้ำบ่อย และเกิดระหว่าง machine wallets แบบ permissionless

ทำไม ERC-8183 ถึงสำคัญกว่าที่เห็น

สิ่งที่น่าสนใจของ ERC-8183 ไม่ใช่แค่มี escrow แต่คือมันออกแบบให้ต่อยอดได้ ในมาตรฐานนี้มีระบบ Hooks ซึ่งเป็น logic เสริมที่นักพัฒนาสามารถเสียบเพิ่มเข้าไปได้ เช่น

  • ตรวจ allowlist หรือเงื่อนไขก่อน fund
  • อัปเดต reputation หลังงานเสร็จ
  • ตั้ง logic แบ่งค่าธรรมเนียม
  • ทำ workflow ที่ซับซ้อนขึ้น เช่น fund transfer, bidding, privacy logic

ในอีกด้านหนึ่ง ERC-8004 ทำหน้าที่เป็นชั้นตัวตน, ชื่อเสียง, ความยอมรับสำหรับ agents โดยเสนอวิธีให้ agents ถูกค้นหา เลือกใช้งาน และตรวจสอบความน่าเชื่อถือได้ข้ามขอบเขตขององค์กร

ถ้าสองชิ้นนี้ถูกใช้งานควบคู่กันจริง VIRTUAL ก็มีสิทธิ์ขยับจากการเป็นแค่แพลตฟอร์มออก agent ไปสู่การเป็นผู้เล่นในชั้น settlement ของ agent economy

แล้ว VIRTUAL ได้ประโยชน์ตรงไหน?

นี่คือคำถามสำคัญที่สุด — ตอนนี้โทเค็น VIRTUAL ยังมีบทบาทเป็นสินทรัพย์หลักใน ecosystem โดยเฉพาะฝั่ง launch mechanics และการจับคู่สภาพคล่องของ agent tokens กับ $VIRTUAL ในระบบ launchpad

แต่ปัญหาคือ: ERC-8183 เป็น open standard

แปลว่าถ้ามาตรฐานนี้ได้รับการยอมรับจริง คนอื่นก็สามารถเอาไปใช้ได้โดยไม่จำเป็นต้องสร้าง demand กลับมาที่โทเค็น VIRTUAL โดยอัตโนมัติ

นี่คือสิ่งที่เป็น "open standard paradox" — โปรเจกต์อาจชนะในระดับ narrative แต่โทเค็นจะชนะหรือไม่ ขึ้นอยู่กับว่า Virtuals จะกลายเป็น liquidity hub หลักของ agent commerce ได้ไหม, builders จะเลือก build บน Virtuals มากกว่าทำเองไหม, และ network effects จะสะสมที่ protocol หรือแค่ที่ standard

สรุปคือ — ฝั่งอุปทานไม่ได้แย่ถึงขั้น uncontrolled inflation แต่ก็ยังมี supply overhang อยู่จริง ถ้า adoption โตไม่ทัน การปล่อย treasury ก็ยังเป็นแรงกดต่อ valuation ได้

โครงสร้างเทคโนโลยี

เอกสารของ Virtuals ระบุว่า agent ใน ecosystem ถูกสร้างเป็น NFT ที่มี token-bound address/vault ของตัวเอง เพื่อใช้ถือทรัพย์สินและผลงานที่เกี่ยวข้องกับ agent นั้นๆ บนเชน

นี่แปลว่า agent ไม่ได้เป็นแค่หน้าอินเทอร์เฟซหรือ character แต่ถูกออกแบบให้มีทั้ง identity, wallet/account, contribution history และ economic layer

เมื่อเอามาประกบกับ ERC-8004 และ ERC-8183 ภาพที่ได้คือ stack ที่ค่อนข้างชัดเจนสำหรับโลกที่ agents จะเริ่มมีบทบาทเชิงเศรษฐกิจ

จุดแข็งของ Thesis

Strength 01

จาก Product story สู่ Protocol story — ตลาดมักให้ค่าสูงกว่ากับ infra ที่คนอื่นต้องใช้ มากกว่ากับแอปที่ผู้ใช้อาจเลิกเล่นเมื่อไรก็ได้

Strength 02

อยู่ใกล้ Ethereum มากขึ้น — ERC-8183 อยู่บน EIP repo และสเปกเชื่อมกับ ERC-8004 โดยตรง ไม่ใช่แค่ marketing partnership แต่เข้าไปอยู่ในชั้นมาตรฐานของ ecosystem

Strength 03

Narrative เปลี่ยนฐานผู้เล่น — จากเหรียญสาย AI meme-ish ไปสู่ dev, infra builders, bot engineers, DeFi-native users และนักลงทุนที่มองมาตรฐานและ middleware

ความเสี่ยงหลัก

Risk 01

มี Narrative แต่โทเค็นไม่ capture value — ERC-8183 อาจถูก adopt กว้าง แต่ถ้า adoption ไม่ไหลกลับมาที่ VIRTUAL token ก็อาจเกิดสถานการณ์ที่ "ecosystem ชนะ แต่เหรียญไม่ชนะ"

Risk 02

Web2 อาจชนะด้วย UX — ถ้า OpenAI, Anthropic หรือผู้เล่นรายใหญ่เปิด agent marketplace ที่ใช้ง่ายกว่า เร็วกว่า และจ่ายด้วย fiat ได้ friction ต่ำกว่า ตลาด mass ก็มีโอกาสสูงที่จะเลือกทางนั้น

สรุป

มันไม่ใช่แค่การเดิมพันว่า AI agents จะดังหรือไม่ แต่คือการเดิมพันว่า โลกจะต้องมี commerce layer สำหรับ agents บนเชนหรือเปล่า — และถ้ามี Virtuals จะกลายเป็นผู้เล่นหลักของชั้นนั้นได้ไหม

Thesis นี้น่าสนใจกว่าเดิมมาก เพราะมันขยับจากตลาดเฉพาะกลุ่มไปสู่โจทย์ใหญ่ระดับ infrastructure แต่ในขณะเดียวกัน investor ต้องเชื่อ 2 ชั้นพร้อมกัน: มาตรฐาน ERC-8183 จะถูกใช้งานจริง และ narrative จะสร้าง demand ได้มากพอโดยไม่ต้องพึ่ง foundation

สิ่งที่ควรจับตาต่อจากนี้:

  • Adoption ของ projects ที่เริ่มใช้ ERC-8183
  • Virtuals จะกลายเป็น default venue / liquidity hub ของ agent commerce ได้หรือไม่
  • Fee flows และกลไก value accrual ที่สะท้อนกลับมายังโทเค็น
  • การเติบโตของ builder ecosystem มากกว่ากระแสเก็งกำไรระยะสั้น
  • การสื่อสารจากทีมเรื่อง token capture ให้ชัดขึ้น
